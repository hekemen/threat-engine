The admin listener binds 127.0.0.1 on each node, so the toggle is not reachable
from other pods or off-host. `kubectl port-forward` and `kubectl exec` are the
intended access paths. The admin unix socket is at {{ .Values.admin.socketPath }}
inside the pod{{ if .Values.admin.socketHostPath }} and on the node at {{ .Values.admin.socketHostPath }}{{ end }}.

Check the current state and the blocklist size:
  kubectl exec -n {{ .Release.Namespace }} daemonset/{{ include "threat-engine.fullname" . }} -- threat-engine enforce status
  kubectl port-forward -n {{ .Release.Namespace }} daemonset/{{ include "threat-engine.fullname" . }} 19090:{{ .Values.http.port }}
  curl -s http://127.0.0.1:19090/metrics | grep threat_engine_
  curl -s 'http://127.0.0.1:19090/check?ip=1.2.3.4'

On a node, verify the kernel state directly:
